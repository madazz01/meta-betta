# Brief 08 — Slash commands (/usage, /resume, /model …)

Read `AGENTS.md` first. Briefs 01–05 must be done (06–07 optional).

## Goal
Typing `/` in the chat box shows a small menu of shortcuts, like other agent chat panels. Each one does something real through the Muse SDK or our brain folder. Results show as compact cards, not walls of text.

## Commands
| Command | What it does | Source |
|---|---|---|
| `/help` | Lists these commands, one line each | static |
| `/new` | Start a fresh chat (same as the New chat button) | brief 03 |
| `/resume` | Pick from recent sessions in this workspace (name/title, last updated, turn count) and switch to it | MSP `session/list` (filter by `workspaceRoot`, newest first) + `resumeSession` |
| `/save` | Save my day | brief 05 |
| `/usage` | This session: input/output/total tokens + **estimated cost** (label it "estimate"); today across sessions (sum what we've seen, stored per day in globalState); when the provider's usage limit resets, if reported; link "Full usage on the Meta dashboard" → https://dev.meta.ai/platform | MSP `session/tokenUsage` (cumulative counters + server `cost`), rate-limit reset field if present |
| `/model` | Show the current model and switch (e.g. `muse-spark-1.3` vs `muse-spark-1.3-contributor`). When the contributor model is selected, show one line: "Runs on your free credits, and Meta may use what you type to improve their models. Don't paste anything private." | MSP `session/setModel`, `session/modelChanged` |
| `/compact` | Shrink the conversation when it gets long; say plainly what happened ("Tidied up the chat history, kept the important bits") or "Nothing to tidy yet" on noop | MSP `session/compact` (ack may be `noop`) |
| `/recap` | A short "where we're up to" summary of this session, generated by Muse | MSP recap (`recap/completed`; sanitize the text, it's model output) |
| `/goal` | Pin a goal for this chat: `/goal build the shopping list page` sets it; `/goal` alone shows it; `/goal pause`, `/goal resume`, `/goal edit <text>`, `/goal clear`. Shows the pinned goal card (see Build 6) | MSP `goal/set`, `goal/edit`, `goal/pause`, `goal/resume`, `goal/clear` + `session/goalChanged` (Goal: objective, percentComplete, status, currentWork, nextWork) |
| `/side` | Ask a quick off-topic question without derailing the job; answer shows in a small side card | MSP `session/sideChat` |
| `/fork` | Try another approach from here without losing this one (also "Try another way from here" on any message) | MSP `session/fork` |
| `/tasks` | What's running: workflows, helpers, terminals; Stop each or Stop all | MSP `task/list`, `task/stop`, `task/stopAll` |
| `/skills` | Browse ready-made skills, turn them on or off | MSP `skill/list`, `skill/setActivation` |
| `/plugins` | Browse and install plugins | MSP `plugin/list`, `plugin/install` |
| `/effort` | Quick / normal / deep thinking (also a chip in the input bar) | MSP `session/setReasoningEffort` |
| `/export` | Save this conversation to a Markdown file | build from history, or CLI `muse export` |
| `/brain` | Focus the Brain panel and open `brain/project.md` | brief 04 |
| `/stop` | Stop the current job | brief 02 (`turn/interrupt`) |
| `/clear` | Clear the panel view only (the session and brain stay) | UI only |

Full feature inventory with "when it helps": [`docs/muse-features.md`](../muse-features.md). The `/` menu must list every command here with its one-line description, so nothing is hidden.

## Build
1. `extension/src/commands/slash.ts`: a registry `{ name, description, run(ctx) }`, plus a pure parser (`"/usage"` → command, `"/model muse-spark-1.3"` → command + args; unknown → "I don't know /xyz, type /help"). Unit-test the parser and registry lookups.
2. Webview: typing `/` at the start of the input opens a filtered menu (arrow keys + Enter, Esc closes, click works). The menu shows name + one-line description.
3. Find the exact SDK/MSP calls in `node_modules/@muse-code/sdk/dist/src/msp.d.ts` and the facade (`facade/*.d.ts`); prefer facade methods, fall back to `connection.command`/request for MSP methods the facade doesn't wrap. If a method isn't available in 1.4.14, show "Not available in this version of Muse Code yet" rather than failing.
4. A small **status bar item** in VS Code: "☕ Muse · 12.4k tokens · ~$0.03" for the current session (click → `/usage`). Update when `session/tokenUsage` changes.
5. All card text plain and short.
6. **Pinned goal card:** while a goal is set, a slim card stays pinned at the top of the chat: `🎯 <objective>`, a progress bar from `percentComplete` (clamp the display to 0–100; the raw value can exceed 100), `Now: <currentWork> · Next: <nextWork>` when present, the status, and [Pause]/[Resume] [Clear] buttons. It updates live on `session/goalChanged` and disappears on `null`. Save my day (brief 05) also writes the goal and its percent into the `project` section so tomorrow's catch-up knows where the goal is at. Muse's goal commands go through the connection we hold (brief 02's real Stop).

7. **Quick-action buttons (Bryan's top five, 29 Oct):** the most useful commands get buttons, not just slash commands. Undo is already in the header. Add a slim row of chips just above the message box: `🎯 Goal` · `💬 Side question` · `🔀 Fork` · `📊 Usage`, each with a plain-words tooltip (e.g. "Ask something off-topic without muddling the main job"). Goal → asks for the goal, then pins the goal card (Build 6). Side question → opens a small side box; the answer appears there, main chat untouched (`session/sideChat`). Fork → "Try another way from here" (`session/fork`), also offered on each message. Usage → the /usage card. Keep the row compact; it must not crowd the input on a narrow sidebar (collapse to icons only when narrow).

8. **Tips for the new buttons (nudges.ts):** add nudge ideas for Goal, Fork and Usage pointing at the new chips (Bryan's top five are undo, usage, side question, goal, fork: keep those five first in the list). Point the side-question tip at the 💬 chip. Remove the "voice note (Alt+V in the Muse terminal)" tip: there's no terminal in Meta Betta; bring it back only if a 🎤 button is added.

## Done when

- `/` opens the menu; `/usage` shows real numbers after a turn; `/model` switches and the next turn uses the new model; `/resume` lists earlier sessions and switching works; `/compact` and `/recap` respond sensibly; unknown commands give the friendly message.
